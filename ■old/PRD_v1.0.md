# To-do 웹앱 PRD

| 항목 | 내용 |
| --- | --- |
| 문서 버전 | v1.0 |
| 프로젝트 | To-do MVP (HTML/CSS/JavaScript) |
| 상태 | 구현 준비 (Ready for Development) |
| 우선순위 | P0 — 모든 요구사항 MVP 필수 |
| 개발 방식 | 순수 HTML, CSS, JavaScript / 프레임워크·외부 라이브러리 없음 |
| 데이터 저장 | 브라우저 `localStorage`만 사용 |

## 1. 프로젝트 배경과 목표

### 1.1 문제 정의
사용자가 브라우저에서 간단히 할 일을 기록하고 완료 여부를 관리할 수 있어야 한다. 별도 계정이나 설치, 서버 없이 사용하고, 페이지를 새로고침해도 같은 브라우저에 저장된 목록이 유지되어야 한다.

### 1.2 목표
- 사용자가 할 일을 **추가·완료 전환·삭제**할 수 있다.
- **전체 및 완료 건수**를 현재 데이터와 일치하게 표시한다.
- 정상적으로 `localStorage`를 사용할 수 있는 환경에서 **새로고침 후에도 데이터가 유지**된다.
- GPT → Claude → Cursor → Notion의 협업 연습에 활용할 수 있도록 구현·검수 기준을 문서화한다.

### 1.3 성공 기준
- §5의 모든 기능별 완료 조건(AC-01~AC-07)을 통과한다.
- 페이지에서 서버 요청이나 외부 API 호출 없이 동작한다.
- `localStorage`가 제한된 환경에서도 앱이 중단되지 않고 사용자가 현재 화면에서 조작할 수 있다(단, 지속 저장은 보장하지 않음).

## 2. 사용자와 핵심 시나리오

**대상 사용자:** 개인용 할 일 목록을 가볍게 관리하려는 단일 사용자.

**핵심 흐름:** 페이지 열기 → 할 일 입력 → 추가 → 체크박스로 완료 처리 → 완료 건수 확인 → 필요 시 삭제 → 새로고침 후 결과 확인.

**기본 가정:** 계정, 다중 사용자, 기기 간 동기화는 없다. 데이터는 해당 브라우저의 해당 저장 영역에만 존재한다.

## 3. 범위와 기술 제약

### 3.1 MVP 포함
할 일 추가, 전체 목록 표시, 완료/미완료 토글, 개별 삭제, `localStorage` 저장 및 복구, 전체/완료 건수 표시, 빈 목록·유효성·저장 실패 안내.

### 3.2 구현 제약
- **사용 기술:** `index.html`, `styles.css`, `app.js`만으로 동작하도록 구현한다. 필요 시 문서 `PRD.md`를 함께 둔다.
- **금지:** React/Vue, TypeScript, npm 패키지, CSS 프레임워크, CDN, 외부 폰트, 백엔드, DB, 로그인, 쿠키 기반 동기화, 외부 API.
- **실행:** 별도 빌드 없이 `index.html`을 브라우저에서 연다. 단, `file://` 주소에서의 `localStorage` 동작과 영속성은 브라우저마다 다를 수 있으므로 실제 사용 환경에서 확인한다. 저장 접근이 막힌 경우 §6의 실패 처리를 따른다.
- **상태 원천:** 실행 중 JavaScript 메모리의 `todos` 배열 하나만 원천 상태로 사용하고, 변경 때마다 화면을 다시 반영한 뒤 저장을 시도한다.

## 4. 핵심 기능 및 상세 요구사항

| 요구사항 ID | 기능 | 우선순위 | 상세 요구사항 |
| --- | --- | --- | --- |
| **FR-01** | 할 일 추가 | P0 | 입력 필드와 `추가` 버튼을 제공한다. 버튼 클릭 또는 입력 필드에서 Enter로 추가한다. 양 끝 공백을 제거한 1~100자 문자열만 허용한다. 유효한 항목은 **목록 맨 아래**에 `completed: false`로 추가하고 입력창을 비우며 입력창에 포커스를 유지한다. 동일 문구 중복은 허용한다. |
| **FR-02** | 목록 표시 | P0 | 각 항목에 체크박스, 할 일 텍스트, `삭제` 버튼을 표시한다. 항목은 추가 순서를 유지한다(정렬·자동 이동 없음). 미완료/완료 항목 모두 표시한다. 목록이 비면 `할 일이 없습니다. 새로운 할 일을 추가해 보세요.` 문구를 표시한다. |
| **FR-03** | 완료 상태 토글 | P0 | 각 체크박스로 `completed`를 `false ↔ true` 전환한다. 완료 항목에는 취소선과 구분 가능한 시각적 스타일을 적용한다. 완료를 해제하면 원래 스타일로 복귀한다. 완료 여부 변경으로 항목 순서는 바뀌지 않는다. |
| **FR-04** | 개별 삭제 | P0 | 각 항목의 `삭제` 버튼 클릭 시 해당 항목만 **즉시 삭제**한다. 별도 확인창과 실행 취소 기능은 제공하지 않는다. |
| **FR-05** | 로컬 저장·복구 | P0 | 앱 시작 시 정해진 키의 `localStorage`를 읽어 상태를 복원한다. 추가·완료 토글·삭제 이후 저장을 시도한다. 저장값은 §7의 JSON 스키마를 따른다. 읽기·파싱·쓰기 실패는 앱 크래시 없이 처리한다. |
| **FR-06** | 건수 표시 | P0 | `완료 {completedCount}건 / 전체 {totalCount}건` 형식으로 표시한다. `totalCount = todos.length`, `completedCount = completed === true` 항목 수다. 추가·토글·삭제·초기 로딩 때 즉시 갱신한다. |
| **FR-07** | 입력·상태 피드백 | P0 | 공백만 입력하거나 글자 수 범위를 위반한 경우 항목을 추가하지 않고 입력창 근처에 오류를 표시한다. 저장 실패 시 별도 안내 문구를 보여준다. 정상 입력으로 재시도하면 입력 오류를 없앤다. |

### 4.1 입력 규칙
- `<input type="text">` 단일행 입력 필드를 쓴다. 최대 길이는 **양 끝 공백 제거 후 100자**이다.
- 공백만 입력하거나 비어 있으면 `할 일을 입력해 주세요.`를 보여준다.
- 양 끝 공백을 제거한 문자열이 100자를 넘으면 `할 일은 100자 이내로 입력해 주세요.`를 보여준다. 값은 추가하지 않는다.
- `Enter`는 입력 중에만 추가 동작을 수행한다. 빈 입력으로 Enter를 누르면 오류가 표시된다.
- 빈 목록에서의 삭제나 체크박스 조작은 해당 UI 자체가 없으므로 발생하지 않는다.

### 4.2 표시 규칙
- 텍스트가 길면 컨테이너 너비에 맞춰 줄바꿈한다. 숨기거나 임의로 자르지 않는다.
- 완료 건수는 완료 항목만, 전체 건수는 완료와 미완료를 모두 포함한다.
- 초기 상태와 목록이 모두 삭제된 상태에서는 `완료 0건 / 전체 0건`으로 표시한다.

## 5. 화면 구성 및 기능별 완료 조건

### 5.1 단일 화면 레이아웃

```text
┌────────────────────────────────────────┐
│                 My To-do               │
│                                        │
│  [할 일을 입력하세요...          ] [추가] │
│  (입력 오류가 있으면 이 위치에 표시)       │
│                                        │
│  완료 1건 / 전체 2건                    │
│                                        │
│  ☐  장보기                       [삭제]  │
│  ☑  운동하기 (취소선)              [삭제]  │
│                                        │
│  (저장 실패 시 이 위치에 안내)            │
└────────────────────────────────────────┘
```

- **헤더:** `My To-do` 제목.
- **입력 영역:** 입력 필드(placeholder: `할 일을 입력하세요...`), `추가` 버튼, 입력 오류 영역.
- **요약 영역:** `완료 N건 / 전체 M건`.
- **목록 영역:** 할 일마다 체크박스·텍스트·삭제 버튼. 목록이 비면 빈 상태 안내 문구.
- **안내 영역:** 저장 또는 복구 오류 발생 시 상태 메시지.
- **반응형:** 최소 320px 폭에서도 콘텐츠가 가로로 넘치거나 조작 버튼이 겹치지 않아야 한다.

| 상황 | 처리 방식 | 사용자 안내 |
| --- | --- | --- |
| 입력이 비어 있거나 공백뿐임 | 추가 취소, 기존 목록 유지 | `할 일을 입력해 주세요.` |
| 공백 제거 후 100자 초과 | 추가 취소, 입력 유지 | `할 일은 100자 이내로 입력해 주세요.` |
| 동일 문구 반복 입력 | 서로 다른 ID로 각각 추가 | 별도 안내 없음 |
| 저장 키 없음 (최초 실행) | 빈 배열로 시작 | 빈 목록 문구만 표시 |
| 저장된 문자열이 잘못된 JSON | 빈 배열로 시작, 기존 잘못된 값을 로딩 중 자동 덮어쓰지 않음 | `저장된 데이터를 불러오지 못했습니다. 새 목록으로 시작합니다.` |
| JSON 구조/버전이 다름 | 빈 배열로 시작, 로딩 중 자동 덮어쓰지 않음 | `저장된 데이터 형식을 확인할 수 없어 새 목록으로 시작합니다.` |
| 저장 배열 내 일부 항목의 형식이 잘못됨 | 유효한 항목만 복원하고 잘못된 항목은 무시. 이 단계에서 자동 저장하지 않음 | `일부 저장 항목을 불러오지 못했습니다.` |
| `localStorage` 읽기 실패 (차단/권한 등) | 빈 목록의 메모리 모드로 시작 | `브라우저 저장소에 접근할 수 없습니다. 새로고침하면 변경사항이 사라질 수 있습니다.` |
| `localStorage` 쓰기 실패 (용량/권한 등) | 메모리 목록 및 화면 변경은 유지, 이후 변경 때도 저장 재시도 | `변경사항을 저장하지 못했습니다. 새로고침하면 사라질 수 있습니다.` |
| 항목 삭제 | 확인 모달 없이 즉시 삭제 | 별도 안내 없음 |

오류 메시지는 화면에 표시하되 `alert()`는 사용하지 않는다. 입력 오류와 저장 오류는 별도 영역으로 다뤄 서로를 덮어쓰지 않는다.

## 7. 데이터 및 상태 설계

### 7.1 저장 규약

- `localStorage` 키: **`todo-mvp.v1`** (정확히 일치)
- 저장 시 `JSON.stringify`로 아래 객체 하나를 저장한다.
- 상태가 변하지 않은 단순 렌더링에는 저장하지 않는다.

```json
{
  "version": 1,
  "todos": [
    { "id": "todo-001", "text": "장보기", "completed": false },
    { "id": "todo-002", "text": "운동하기", "completed": true }
  ]
}
```

### 7.2 필드 규칙

| 필드 | 타입 | 규칙 |
| --- | --- | --- |
| `version` | number | 정확히 `1` |
| `todos` | array | 목록 순서가 표시 순서 |
| `id` | string | 각 항목에서 고유한 비어 있지 않은 문자열. 추가 시 기존 ID와 충돌하지 않게 생성. 삭제/토글의 식별자로 사용 |
| `text` | string | 양 끝 공백 제거 후 1~100자 |
| `completed` | boolean | 새 항목은 `false`, 토글할 때 반전 |

초기 복구 시 루트 객체, 버전, 배열 여부를 검사한다. 항목이 일부 잘못된 경우에는 유효한 `id`·`text`·`completed`를 가진 항목만 보존하며 중복 ID는 처음 등장한 항목만 유지한다. 저장 데이터에 없는 임의의 상태(날짜·우선순위 등)는 만들지 않는다.

### 7.3 상태 변경 순서
1. 사용자의 입력/클릭 이벤트 수신.
2. 입력 검증 또는 대상 `id` 확인.
3. `todos` 배열 갱신.
4. 목록·건수·빈 상태 화면 갱신.
5. 갱신된 전체 상태를 `localStorage`에 저장 시도.
6. 저장 결과에 따라 안내 메시지 갱신.

**보안:** 사용자가 입력한 할 일 문자열은 DOM에 일반 텍스트(`textContent` 등)로 렌더링한다. 사용자 입력을 HTML로 해석하는 `innerHTML` 문자열 결합은 금지한다.

## 10. Cursor 구현 지시 및 산출물

### 10.1 디렉터리 구조

```text
todo-app/
├── PRD.md
├── index.html
├── styles.css
└── app.js
```

### 10.2 구현 원칙
- `index.html`에서 `styles.css` 및 `app.js`만 로드한다. 외부 리소스는 참조하지 않는다.
- 앱 초기화, 렌더링, 추가, 토글, 삭제, 로드, 저장 기능을 JavaScript에서 명확히 분리한다.
- 이벤트 핸들러가 직접 여러 DOM 조각을 따로 갱신해 불일치가 생기지 않도록 **상태 변경 후 공통 렌더 함수**를 호출한다.
- 버튼·입력·체크박스가 모바일과 키보드에서 조작 가능하도록 기본 HTML 시맨틱 요소를 사용한다.
- 범위 외 기능을 임의로 추가하지 말고, 의사결정이 필요한 미정 사항은 구현 전 문서로 남긴다.
